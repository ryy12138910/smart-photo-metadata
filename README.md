# 照片水印信息整理工具

[English](README_EN.md)

用于批量整理工程现场、巡检、测绘等照片中的经纬度和拍摄时间。程序读取照片画面上的水印，生成可人工审核的 Excel；确认后，再把结果写入新照片的属性中。

## 背景

现场照片往往已经在画面上显示位置和时间，但文件属性中缺少这些信息。照片数量较多时，逐张查看、抄录和修改不仅耗时，也容易出现数字、方向或日期错误。

本工具把这项工作整理为一个可重复的流程：

1. 批量识别照片水印；
2. 将结果集中到 Excel 中审核；
3. 只把确认通过的结果写入新照片；
4. 保留原照片和原目录结构，便于核查与归档。

## 识别方式

- **纯 OCR（本地处理）**：照片不发送给第三方服务，适合离线或敏感数据场景。
- **OCR + 大模型 API**：用具备图片理解能力的大模型复核异常或缺失结果。API 服务商和模型不受限制，只要提供兼容的图片对话接口即可。

## 快速开始

### 使用便携包

普通用户请从 [GitHub Releases](https://github.com/ryy12138910/smart-photo-metadata/releases/latest) 下载 `PhotoMetadataTool-Windows-x64.zip`，不要使用仓库首页的“Code → Download ZIP”（后者是源代码）。

下载后解压到普通文件夹，双击 `PhotoMetadataTool.exe` 或 `启动程序.bat`。便携包已经包含 Python 依赖和离线 OCR 组件，不需要安装 Python、运行 pip，也不需要配置环境变量或程序路径。界面右上角可切换中文和 English，英文界面生成的审核表也使用英文表头与审核选项。

### 从源代码启动

只有需要修改程序的开发者才建议使用源码。双击 `启动程序.bat` 后，首次运行会自动准备所需组件；该方式要求电脑已安装 Python 且能够访问依赖下载源。如果安装失败，请改用上面的 Windows 便携包。

## 操作流程

### 1. 识别与审核

1. 选择照片根目录；
2. 选择审核表保存位置；
3. 选择“纯 OCR”或“OCR + 大模型 API”；
4. 如果使用 API，填写完整 API 地址、模型名称和 API Key；
5. 点击“开始生成审核表”。

使用 API 时，所选模型必须支持图片输入。API Key 只提供给当前运行任务，不会写入审核表、缓存或日志。

任务结束后打开审核表，重点检查“待核”记录。修正经纬度或拍摄时间后，将确认无误的记录标记为“通过”并保存。

#### 处理选项说明

| 选项 | 说明 |
| --- | --- |
| 识别方式 | “纯 OCR”完全在本机处理；“OCR + 大模型 API”会把需要复核的图片发送到所填写的 API。 |
| API 地址 | 服务商提供的完整图片对话接口地址。仅在选择大模型 API 时使用。 |
| 模型名称 | 服务商要求填写的模型标识；该模型必须支持图片输入。 |
| API Key | 当前任务访问模型服务所需的密钥。程序不会保存密钥。 |
| API 复核范围 | “仅复核异常结果”调用次数较少；“复核所有缺少属性的图片”覆盖更全面，但会增加调用量和费用。 |
| 审核表图片 | 可选择只保留照片链接、嵌入压缩缩略图或嵌入原图。原图模式会显著增大 Excel 文件。 |
| 路径筛选 | 只处理完整路径中包含该文字的照片；留空表示处理所选目录下的全部照片。适合先测试某个子目录。 |
| 处理数量上限 | 限制本次最多处理多少张照片；填写 `0` 表示不限制。适合首次小批量测试。 |
| 同目录离群阈值（米） | 同一直接文件夹内，某张照片的 OCR 坐标偏离其他照片典型位置超过该距离时，将标记复核。默认 `500` 米；设得过小可能产生较多待核记录。 |

### 2. 写入新照片

1. 切换到“写入新照片”；
2. 选择原始照片目录、审核后的 Excel 和输出目录；
3. 第一次建议保留“仅演练”，先检查结果报告；
4. 确认无误后取消“仅演练”，再次运行生成新照片。

程序默认不修改原照片，只补充缺失属性。除非确有需要，不建议开启“覆盖已有 EXIF”。

#### 写入选项说明

| 选项 | 说明 |
| --- | --- |
| 仅演练 | 只检查审核表并生成报告，不创建新照片。第一次运行建议保持勾选。 |
| 覆盖已有 EXIF | 允许审核表中的值替换原图已有的 GPS 或拍摄时间。即使开启，程序仍输出到新目录，不直接修改原照片。 |

## 输出内容

| 输出 | 用途 |
| --- | --- |
| `metadata_review.xlsx` | 集中查看、修正和确认识别结果 |
| `photos_with_exif/` | 保存补充属性后的新照片 |
| `write_result_report.xlsx` | 查看每张照片的处理状态和失败原因 |

识别过程中会在审核表旁生成断点文件。任务中断后，使用相同的照片目录和审核表位置再次运行即可继续。

## 使用建议

- 正式批量处理前，先用少量照片完成一次全流程测试；
- 输出目录不要选择原始照片目录；
- 涉及敏感照片时使用纯 OCR，或确认所接入 API 服务符合数据管理要求；
- OCR 和大模型结果都可能出错，正式归档前应完成必要的人工审核。

## 常见问题

### 提示 “Umi-OCR local API did not become ready”

请确认下载的是 GitHub Releases 中的 Windows 便携包，并且已经把整个 ZIP 完整解压后再运行；不要直接在压缩包预览窗口中双击 EXE，也不要单独复制两个 EXE。`runtime` 文件夹必须和 `PhotoMetadataTool.exe` 放在同一目录。

`v1.0.0` 存在 Umi-OCR 启动兼容问题，请升级到 `v1.0.4` 或更高版本。如果新版仍无法启动，请检查安全软件是否拦截 `runtime` 中的 `Umi-OCR.exe`，以及本机端口 `1224` 是否被其他程序占用。

## 支持范围

- 识别与审核：JPG、JPEG、PNG、BMP、WebP；
- 写入照片属性：JPG、JPEG、PNG；
- 主要面向 Windows 10/11 64 位系统。

## 开发者构建

在 Windows PowerShell 中运行 `build_portable.ps1`，可生成包含离线 OCR 组件的便携压缩包。构建结果位于 `dist` 目录。仓库也包含只读权限的 Windows 自动构建流程，可手动运行或通过 `v*` 标签触发；正式发布包由维护者核验后上传到 GitHub Releases。
